# 场景包：ICT / 云安 / 企业软件（ict）

适用投递方向：深信服、新华三、网宿、中兴（部分岗）、金蝶、科力普、视源（企业/教育信息化相关）等。

本包提供：**As-Is 分析要点、需求类型、我方 vs 竞品对比维度、提问、讲解骨架、异议预案**。  
具体产品规格、授权、报价、竞品指标一律待使用者结合 **公司官方资料** 填写；输出仅为个人备战草稿。

---

## 1. 场景边界

### 覆盖

- 网络安全 / 零信任 / VPN 收敛 / 云安全相关方案沟通
- 企业软件（ERP/云服务）试点与集成边界澄清
- 分支机构、远程接入、权限与审计类需求摸底

### 不覆盖（标为缺口或转专家）

- 详细网络拓扑设计与容量精确测算（无数据则待确认）
- 代码级二次开发估算
- 机器视觉/芯片选型（见 `scene_vision` / `scene_chip`）

## 2. 客户当前在做什么（As-Is 分析要点）

| 线索 | 要写清什么 |
|------|------------|
| 业务对象 | 保护/支撑什么业务（远程运维、分支上网、财务流程等） |

## 3. 标准「产品需求类型」`need_type`（ICT）

| ID | 需求类型 | 客户常说的话 | 讲解时对应的能力位（通用） |
|----|----------|--------------|----------------------------|
| `N-access` | 安全接入与身份 | VPN 乱、账号共用、远程难管 | 身份、接入、设备可信（口径以公司资料为准） |
| `N-policy` | 权限与最小授权 | 权限过大、难回收 | 策略、应用级授权、审批流 |
| `N-audit` | 审计与合规 | 对不上人、等保/审计 | 日志、报表、合规映射说明 |
| `N-branch` | 分支/多站点 | 工厂多、标准不统一 | 分支模板、统一纳管 |
| `N-perf` | 体验与性能 | 卡、慢、专线贵 | 架构体验边界；无数据不承诺指标 |
| `N-integrate` | 集成对接 | 要接 AD/SSO/业务系统 | 标准接口与定制边界 |
| `N-pilot` | 可试点验证 | 先一个点试试 | 试点范围、成功标准、时间盒 |
| `N-ops` | 运维与响应 | 谁来管、出事找谁 | 交付、培训、售后边界 |
| `N-cost` | 范围与拥有成本 | 授权怎么算、怕隐形费用 | 范围结构；价格走商务 |
| `N-migrate` | 迁移与并存 | 旧 VPN/旧系统怎么切 | 并存、灰度、回退策略 |

## 4. 我方 vs 其他产品：推荐对比维度

| 维度 ID | 对比维度 | 客户常怎么比 | 讲解注意 |
|---------|----------|--------------|----------|
| `D-access` | 接入与身份能力 | 「能不能管住人/设备」 | 不编造并发/性能数字 |
| `D-policy` | 细粒度权限 | 「能不能控到应用」 | |
| `D-audit` | 审计合规 | 「能不能过审计」 | 等保级别待确认 |
| `D-branch` | 多分支落地 | 「能不能统一管」 | |
| `D-pilot` | 试点可决策性 | 「能不能先试」 | 主打成功标准 |
| `D-integrate` | 集成生态 | 「接不接得上」 | 协议未核实则待确认 |
| `D-ops` | 运维与服务 | 「谁来值守」 | |
| `D-cost` | 授权与范围 | 「怎么计价」 | 不编报价 |
| `D-migrate` | 迁移风险 | 「切不过去怎么办」 | 强调并存与回退 |

无竞品名时：对比「我方方案 vs 客户现状手段（如传统 VPN）」。

## 5. Discovery 必问清单

| # | 问题 | 建议问谁 | 主要验证 |
|---|------|----------|----------|
| Q1 | 当前远程/分支接入怎么做？最大痛点是安全、审计还是体验？ | 安全 / 网络 | As-Is |
| Q2 | 有多少分支/用户/并发粗量级？高峰场景是什么？ | 网络 / 运维 | `N-branch` / `N-perf`（数字待确认） |

| Q6 | 是否接受 1～2 个分支先试点？成功标准怎么写？ | 安全 / 采购 / 项目 | `N-pilot` |

## 6. 讲解骨架

1. 复述客户当前怎么做（As-Is）  
2. 拆 1～3 个主痛点与需求（P*/R*）  
3. 对齐我方产品要点（brief）  
4. 相对竞品或现状：只讲已核实差异；主打试点可决策性  
5. 明确边界与下一步（要资料、定试点、拉售前专家）

## 7. 常见异议

| 异议 | 应对方向 | 不要做的事 |
|------|----------|------------|
| 「先报准确并发/性能」 | 要业务画像与试点度量；不口头报峰值 | 编造 TPS/并发 |
| 「某某更便宜」 | 拉回范围、风险、试点成功标准与 TCO 结构 | 只打价格战 |
| 「我们已有 VPN 够用」 | 对齐审计/共用账号/分支统一等真实痛点 | 否定客户现状而无证据 |
| 「必须无缝替换一周内切完」 | 谈并存与灰度；评估迁移风险 | 打包票无回退 |

## 8. 痛点 → 需求速查

| 客户信号 | 主 need_type |
|----------|--------------|
| 账号共用、远程失控 | `N-access` / `N-policy` |
| 审计对不上、等保 | `N-audit` |
| 分支多、标准乱 | `N-branch` |
| 卡、慢、体验差 | `N-perf` |
| 要接 AD/业务系统 | `N-integrate` |
| 先试点再推广 | `N-pilot` |
| 怕切换失败 | `N-migrate` |
| 怕隐形费用 | `N-cost` |

## 9. 额外约束

1. 无容量/并发数据不承诺性能数字。  
2. 合规结论须标待确认（等保级别等）。  
3. Demo/证据只指向**公司产品**；禁止演示本工具。  
4. 若输入明显是视觉检测/芯片选型，提示切换场景包。
