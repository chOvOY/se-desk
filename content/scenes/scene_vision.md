# 场景包：机器视觉 / 传感 / 工控（vision）

适用投递方向：西克、深视智能、奥普特、信捷、麦格米特、海康（视觉/工业相关岗）等。

本包提供：**As-Is 分析要点、需求类型、我方 vs 竞品对比维度、提问、讲解骨架、异议预案**。  
具体产品参数、型号、报价、竞品指标一律待使用者结合 **公司官方资料** 填写；本工具输出仅为个人备战草稿。

---

## 1. 场景边界

### 覆盖

- 外观/尺寸/定位类机器视觉检测与测量
- 工业传感器选型相关的「应用场景澄清」（光、距、材质、节拍）
- 工控/自动化产线中与「检、测、判」相关的方案沟通

### 不覆盖（标为缺口或转专家）

- 深度定制算法论文级方案
- 整厂 MES/ERP 替换（可记为集成需求，细节转 ICT/交付）
- 芯片器件级电路设计（见未来 `scene_chip`）

## 2. 客户当前在做什么（As-Is 分析要点）

生成「客户当前在做什么」时，按下面线索从纪要中抽取；没有的写缺口。

| 线索 | 要写清什么 |
|------|------------|
| 业务对象 | 检什么工件/缺陷/尺寸，产线属于哪类 |
| 现状手段 | 人工全检/抽检、已有相机或传感器品牌、是否自研 |
| 作业方式 | 在线还是离线、谁看、谁判、不合格怎么流转 |
| 效果与不满 | 漏检/误检/慢/难换型/难对接等客户原话 |
| 已投入 | 是否已买过设备、是否在比三家（有则记下名字） |

As-Is 写完后，才能映射「需要的产品」；不要跳过现状直接推荐。

## 3. 标准「产品需求类型」`need_type`（视觉）

分析痛点时，优先映射到下表（可多选，但主类型只标一个）。

| ID | 需求类型 | 客户常说的话 | 讲解时对应的能力位（通用） |
|----|----------|--------------|----------------------------|
| `N-detect` | 稳定检出 | 漏检、看不出来、不稳定 | 成像稳定性、算法鲁棒、试样可验证 |
| `N-false` | 误检可控 | 误报太多、产线不信 | 阈值策略、阈值阈值、人工复核接口 |
| `N-takt` | 节拍匹配 | 跟不上线速、拖节拍 | 相机/光源/算力与节拍匹配、并行方案 |
| `N-changeover` | 换型友好 | 换品种麻烦、调参久 | 配方管理、快速换型、可视化调参 |
| `N-trace` | 追溯与报表 | 验厂、批次追溯、要报表 | 存图、结果记录、对接上位/MES |
| `N-integrate` | 产线集成 | 和 PLC/机器人/上位对接 | IO/通信协议、联调边界、交付界面 |
| `N-install` | 安装环境适配 | 振动、粉尘、空间、光照乱 | 防护、安装方式、光源与环境方案 |
| `N-poc` | 可验证 POC | 先试再买、要看效果 | 试样流程、成功标准、报告口径 |
| `N-support` | 交付与售后 | 不会调、怕死人、要培训 | 调试支持、培训、备件与响应 |
| `N-cost` | 拥有成本清晰 | 怕隐形费用、要算账 | 硬件范围、软件授权、实施工作量边界 |

## 4. 我方 vs 其他产品：推荐对比维度（vision）

异同分析按维度输出（见 `docs/FIELDS.md` 第 7 节）。本场景优先用下表：

| 维度 ID | 对比维度 | 客户常怎么比 | 讲解注意 |
|---------|----------|--------------|----------|
| `D-detect` | 检出稳定性 / 适用缺陷类型 | 「能不能看出来」 | 无试样不报具体率 |
| `D-false` | 误检与产线接受度 | 「会不会乱停线」 | 强调阈值与调参，不贬低对方 |
| `D-takt` | 节拍与在线能力 | 「跟不跟得上」 | 数字待确认 |
| `D-changeover` | 换型与易用性 | 「换品种麻烦不」 | 可对比操作路径，忌空口「我们最好用」 |
| `D-integrate` | 集成与通信 | 「接不接得上 PLC/MES」 | 协议未核实则标待确认 |
| `D-trace` | 存图 / 追溯 / 报表 | 「验厂要不要」 | |
| `D-install` | 安装与环境适应性 | 「现场能不能装」 | |
| `D-poc` | 试样 / POC 支持 | 「能不能先试」 | 比流程与成功标准，不比空头承诺 |
| `D-support` | 交付、培训、售后 | 「谁来调、坏了怎么办」 | |
| `D-cost` | 范围与拥有成本口径 | 「到底多少钱、含什么」 | 只谈范围结构，不编报价 |
| `D-brand` | 品牌与行业案例 | 「有没有同行用过」 | 案例须可核实 |

**相同点**：写双方都能满足或客户暂时无感差异的维度。  
**差异点**：只写有 `our_product_brief` / 纪要依据的差异；其余进「待核实」。  
若无竞品名：对比对象改为「我方方案 vs 客户当前手段（人工/旧系统）」。

## 5. Discovery 必问清单（约 10 题）

按本场目标裁剪；摸底场优先前 6 题。

| # | 问题 | 建议问谁 | 主要验证 |
|---|------|----------|----------|
| Q1 | 当前是人工检、抽检，还是已有视觉/传感器方案？效果哪里不满意？ | 质量 / 工艺 | 现状与痛点证据 |
| Q2 | 典型缺陷或检测目标是什么？有没有样本图/实物？合格与不合格的判定标准谁定？ | 质量 / 工艺 | `N-detect`、验收口径 |
| Q3 | 漏检和误检各自的业务后果是什么（客诉、返工、停线、报废）？有没有量级感觉？ | 质量 / 生产 | 影响面与紧急度 |
| Q4 | 产线节拍大约多少？检测是在线还是离线？允许的检测节拍上限？ | 生产 / 设备 | `N-takt` |
| Q5 | 产品品种多少、换型频率如何？换型时希望多久能调通？ | 生产 / 工艺 | `N-changeover` |
| Q6 | 安装位置空间、振动、粉尘、环境光、温度有什么限制？ | 设备 / 现场 | `N-install` |
| Q7 | 结果是否需要存图、批次追溯、对接 PLC/MES/上位？已有接口协议是什么？ | 设备 / IT | `N-trace` / `N-integrate` |
| Q8 | 是否必须先做试样/POC？成功标准怎么写（定性即可，数字待确认）？ | 质量 / 采购 / 项目 | `N-poc` |
| Q9 | 决策链里谁拍板？还有哪些供应商在比？客户最看重的对比维度是效果、价格、交付还是服务？ | 采购 / 项目 | 竞品异同、`D-*` |
| Q10 | 期望的调试支持、培训、验收与售后方式是什么？ | 设备 / 采购 | `N-support` / `N-cost` |
| Q11 | （若已有竞品/旧视觉）对方哪里满意、哪里不满意？是否愿意做同条件试样对比？ | 质量 / 设备 | As-Is 与异同核实 |

### 本场「优先验证 3 问」选取规则

1. 证据为 `assumed` 的关键痛点 → 必问  
2. 影响 `must` 优先级的缺口 → 必问  
3. 与 POC/试样能否启动直接相关 → 必问

## 6. 讲解骨架（现状 → 需要 → 我方差异 → 验证）

讲解顺序建议：先对齐「客户现在怎么做」，再讲「需要什么」，再讲「我方与其它方案异同」，最后落到验证与集成。

### 6.1 通用叙事顺序

1. **复述客户当前在做什么**（As-Is，用客户词确认）  
2. **拆成 1～3 个主痛点与需求**（P* / R*）  
3. **对齐我方产品/能力位**（来自你的产品要点，会前用官方资料复核）  
4. **点出与竞品或现状的异同**（只讲已核实差异；相同点可并列承认）  
5. **给出验证路径**：试样 / 现场 Demo / 联调边界（均为 **公司产品**）  
6. **明确本期边界** → **推进下一步**

### 6.2 能力位 → 建议准备的公司侧材料（占位）

| need_type | 讲解时建议准备（由使用者换成本公司实际材料） |
|-----------|-----------------------------------------------|
| `N-detect` / `N-false` | 同类行业案例、试样报告模板、调参/阈值说明彩页 |
| `N-takt` | 节拍相关选型逻辑说明（不编数字）、硬件组合示意 |
| `N-changeover` | 配方/换型操作说明或演示脚本 |
| `N-trace` / `N-integrate` | 接口清单、联调范围说明书 |
| `N-install` | 安装与防护方案示意、现场调研表 |
| `N-poc` | POC 流程、成功标准空白表、时间盒建议 |
| `N-support` / `N-cost` | 服务内容边界、实施阶段划分（无报价则标待商务） |

## 7. 常见异议与应对骨架

均为「话术方向」，具体参数用公司资料补全。

| 异议 | 应对方向 | 不要做的事 |
|------|----------|------------|
| 「先报个准确检出率」 | 说明依赖试样与工况；提议用 POC 成功标准代替口头承诺 | 随口报 99.x% |
| 「某某竞品更便宜」 | 拉回到漏检成本、误检成本、节拍与交付总拥有成本；请客户给对比维度 | 只打价格战或贬低竞品 |
| 「我们自己也能搭一套」 | 承认可自研；强调稳定量产、换型、交付与售后的差异，邀请试样对比 | 否定客户能力 |
| 「空间/环境太差做不了」 | 先做现场约束清单；讨论安装与光源方案；必要时降范围或改离线 | 未看现场就承诺 |
| 「必须和现有 PLC/MES 无缝对接」 | 澄清协议与数据字段；划清标准接口 vs 定制；拉交付同事评估 | 不懂协议却打包票 |
| 「先试用很久再谈采购」 | 同意验证，但建议时间盒 + 成功标准 + 双方投入边界 | 无限期免费陪跑无目标 |

## 8. 痛点 → 需求类型速查（分析时用）

| 客户信号 | 主 need_type | 常见次要类型 |
|----------|--------------|--------------|
| 漏检、客诉、逃逸缺陷 | `N-detect` | `N-poc`、`N-false` |
| 误报多、产线关掉视觉 | `N-false` | `N-detect`、`N-changeover` |
| 跟不上节拍、成为瓶颈 | `N-takt` | `N-install`、`N-integrate` |
| 换品种要很久、要会编程的人 | `N-changeover` | `N-support` |
| 验厂、批次、要存图报表 | `N-trace` | `N-integrate` |
| 要接机器人/PLC/上位 | `N-integrate` | `N-trace` |
| 现场黑、抖、挤、油污 | `N-install` | `N-detect`、`N-takt` |
| 不试不做决定 | `N-poc` | `N-detect`、`N-cost` |
| 怕调试没人管 | `N-support` | `N-cost`、`N-changeover` |
| 怕隐形费用、范围不清 | `N-cost` | `N-poc`、`N-support` |

## 9. 本场景生成时的额外约束

1. 涉及光学、算法、节拍的结论，无试样一律标 **待确认**。  
2. `need_type` 优先使用本包第 3 节 ID；确需新增时写全称，并标「非标准类型」。  
3. 竞品异同优先使用本包第 4 节维度；无依据不编指标、不贬低竞品。  
4. 讲解提纲中的 Demo/证据必须写「公司产品侧应准备什么」，禁止写「打开销售工程师备战台给客户看」。  
5. 若输入明显是纯网安/ERP/芯片选型，提示使用者切换场景包，不要硬套视觉术语。

## 10. 会前最小输入检查（vision）

开始生成前，若下列任一项缺失，在「缺口」中显式列出：

- [ ] 检什么 / 判什么（目标）  
- [ ] 客户当前在做什么（现状手段与流程）  
- [ ] 在线还是离线、与节拍关系  
- [ ] 是否有样本或可提供试样  
- [ ] 我方产品要点是否已提供（否则无法做「需要对齐我方什么」）  
- [ ] 竞品或对比对象是否已知（否则异同表对现状手段，并生成打探问题）  
- [ ] 本场目标（摸底 / 方案 / 试点）
