# 项目作用与目的

## 一句话

**销售工程师备战台**帮助销售工程师在会前/会后快速整理：「客户现在怎么做、真正要买什么、我方与竞品哪里同哪里不同」，并生成提问清单与讲解提纲草稿；核实后用**公司产品**去见客户。

---

## 目的（为什么做）

1. **先看清客户**：现状流程、痛点、干系人、真正要买的能力类型。  
2. **再对齐产品**：把需求映射到我方能力位，理清与竞品的同/异与话术边界。  
3. **缩短准备时间**：纪要/线索 → 结构化草稿，少从零写分析与对比。  
4. **减少遗漏与乱承诺**：事实/假设/缺口分栏；无依据的参数一律待确认。  
5. **支撑连续拜访**：同一客户名录累计事实与开放缺口，本场只补新纪要。  
6. **跨行业复用**：同一流程，按场景包切换行业语境（工控 / ICT / 芯片等）。

---

## 作用（具体帮你干什么）

| 作用 | 说明 |
|------|------|
| 分析客户当前在做什么 | 梳理 As-Is：流程、现状手段、谁在用、效果与不满 |
| 分析需要的产品是什么 | 从痛点映射到需求类型，并给出「建议对齐的我方能力/产品位」（草稿） |
| 分析我方与竞品异同 | 按维度列出相同点、差异点、可强调点、需谨慎或待核实点 |
| 客户信息结构化 | 事实 / 假设 / 信息缺口分栏 |
| 产出 Discovery 问题 | 验证现状、需求与竞品判断 |
| 产出讲解提纲草稿 | 痛点 → 我方能力 → 公司证据/Demo → 下一步 |
| 标出风险与待确认 | 防止编参数、漏边界、会上拍胸脯 |
| 客户名录与多访 | 记录备战过的客户，累计事实/缺口，避免每访从零开始 |

---

## 明确不是什么（边界）

| 不是 | 原因 |
|------|------|
| 给客户演示的产品 | 客户现场只讲、只演示**公司产品** |
| 官方选型/报价/竞品打击材料 | 输出是草稿，须结合公司官方与合规话术核实 |
| 自动判定「我们一定赢」 | 只做结构化对比，不替你下商务结论 |
| CRM / 自动成交系统 | 不做商机全流程管理与跟进提醒 |
| 替代试样、POC、实验室数据 | 技术与指标无依据时一律「待确认」 |

---

## 正确用法（讲述口径）

- **给谁用**：销售工程师、技术销售、方案顾问等。  
- **怎么用**：输出是草稿 → 结合公司材料与合规要求再梳理 → 向客户讲解并演示**公司产品**。  
- **讲什么结果**：更快看清客户现状与需求、对比更有结构、讲解更贴本场场景、多访信息不丢。

避免听起来像：在卖自研 SaaS，或用本工具替代公司解决方案。

---

## 成功标准（什么叫有用）

对一段真实或模拟纪要（可附我方能力要点与竞品名），能得到可手改的完整草稿，且你改完后能据此：

1. 讲清客户**当前在做什么**；  
2. 讲清客户**需要什么产品/能力**，以及建议对齐的我方产品位；  
3. 讲清**我方与竞品的异同**（有依据、有待确认）；  
4. 带着问题见客户，并按提纲准备**公司产品**的讲解与 Demo；  
5. （若多访）名录里能看见累计事实与仍开放的缺口。
